# QUAL requirements

Requirement text is taken from SPEC.md.

- QUAL-001: One authoritative implementation per business rule.
- QUAL-002: Typed interfaces and explicit module boundaries.
- QUAL-003: No speculative frameworks or premature abstractions.
- QUAL-004: Minimise and audit dependencies.
- QUAL-005: Structured, actionable errors; never conceal uncertain outcomes.
- QUAL-006: Bounded logs, health diagnostics and useful metrics without sensitive data.
- QUAL-007: Update relevant architecture, CLI, installation, security and troubleshooting documentation.
- QUAL-008: Avoid duplicated normative documentation.
- QUAL-009: Review security-sensitive and cross-component changes independently when necessary, using focused reviews rather than permanent reviewer agents.
- QUAL-010: Keep unrelated improvements out of scope.
